# The eval runner and the kill-criteria report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `heph stats` reports how many runs reach merge cleanly (the SPEC's kill criterion), and `heph eval` runs a golden-task suite in throwaway workspaces, checks the hidden oracle, records metrics, and compares two labelled runs with their run-to-run spread.

**Architecture:** Pure modules first: `classifyRun`/`buildStats` for the report, and under `packages/cli/src/eval/` an oracle checker, metrics extraction from a throwaway ledger, and result files with `summarize`/`compare`. Then the workspace setup and the per-run runner (using `openRuntime` with the user's real node config and a throwaway ledger home, and a new `eval` option on `newRun`), then the CLI commands.

**Tech Stack:** TypeScript on Bun, zod 4, `bun test`.

**Spec:** `docs/superpowers/specs/2026-11-07-eval-and-stats-design.md`

## Global Constraints

- Eval runs never push, open PRs or touch the real ledger or repos: clones use `--no-hardlinks`, have every remote removed, and the ledger home is a throwaway directory under the eval home.
- A clean run is merge-ready (`staged` or `finished`) with exactly one `run.plan_ready`, no `human.input` of kind `hint`, `budget_override`, `scope` or `plan_edit`, no `unit.escalated` and no `unit.stalled`; `approve` inputs do not count. Runs with `eval: true` are excluded from the report.
- Headline clean rate = clean / (clean + assisted + did_not_merge); `null` with no closed runs; "below" means under 0.5. Every `heph stats` output carries the footer text `Cannot see: manual edits made outside heph or on GitHub after a PR was opened, nor work done in direct sessions that never went through heph.`
- Eval statuses: `solved`, `unsolved`, `escalated` (an `expect: escalate` task whose planner returned an Escalation; counts as solved), `missed_escalation` (it returned a Plan), `false_escalation` (a task with an oracle whose planner escalated), `error` (the run threw; excluded from rates, reported separately).
- Result files: `<out>/<label>/<task>/run-<k>.json`; default `<out>` is `<suite>/results`; eval home is `<HEPH_HOME>/eval`. No ledger event, schema or projection changes.
- No attribution of any kind in commit messages (project CLAUDE.md overrides any harness reminder).
- `bun test <path>` per task. Baseline in the agent sandbox: about 70 tests in `packages/cli` and `packages/engine` and 18 in `packages/workers` fail before this work (native-sandbox nesting, daemon, landing); tests that bind ports fail with `EPERM` in the sandbox (run them outside it). Compare against a baseline checkout; judge flaky heavy-suite failures by rerunning the file alone. A live `heph eval` run needs model calls, the real game repo and OMP, none of which work in the agent sandbox: do not attempt one.

## Review Focus

- A throwaway eval workspace has no remotes and the real repo's refs and working tree are unchanged after a run; the real ledger gets no event. (Task 3)
- Oracle: hidden tests are copied after the `must_not_touch` diff is taken (they must not count as violations); a non-zero `must_pass` makes the run `unsolved` and names the command; a forbidden path makes it `unsolved` and names the file. (Task 2)
- Escalation accounting: `escalated`, `missed_escalation`, `false_escalation` and `error` land in the right rates and `compare`'s spread. (Tasks 2, 3)
- `heph stats` boundaries: `staged` is merge-ready but `built` is open; `approve` inputs are not hints; a replan or a cancel; eval runs excluded; the window edge. (Task 1)
- `--resume` does not rerun a run whose result file exists, and a run that throws is recorded as `error` without stopping the eval. (Task 3)

**Interfaces:**
- Produces, in `stats.ts`:
  - `type RunClass = "clean" | "assisted" | "did_not_merge" | "open"`.
  - `classifyRun(row: { status: string }, events: { type: string; data?: unknown }[]): { class: RunClass; reasons: string[]; hints: number; replans: number; escalations: number; stalls: number }`. Merge-ready is status `staged` or `finished`; `failed` (cancelled included) and `escalated` are `did_not_merge`; `created`, `planned`, `paused`, `running`, `built` are `open`. Counts: `hints` = `human.input` events whose `data.kind` is `hint`, `budget_override` or `scope`; `replans` = `max(0, run.plan_ready count - 1)` plus `human.input` events of kind `plan_edit`... counted once as `replans = max(run.plan_ready count - 1, plan_edit count)`; `escalations` = `unit.escalated` count; `stalls` = `unit.stalled` count. Merge-ready with all four counts zero is `clean`, else `assisted` with reasons like `replanned`, `2 hints`, `1 escalation`, `1 stall`; `did_not_merge` reasons are `cancelled` (a `run.failed` event with `data.reason === "cancelled by user"`), `failed`, or `planner escalated`.
  - `buildStats(o: { runs: RunRow[]; eventsOf: (runId: string) => { type: string; data?: unknown }[]; since: Date; list?: boolean }): Stats` where `Stats = { schema: 1; since: string; counts: { clean; assisted; did_not_merge; open: number }; clean_rate: number | null; below_threshold: boolean | null; assisted_totals: { hints; replans; escalations; stalls: number }; runs?: { run_id; status; class; reasons: string[] }[]; footer: string }`. It skips `row.eval` runs and runs created before `since`; `below_threshold` is `clean_rate < 0.5` (null when the rate is null).
  - `parseSince(text: string, now?: Date): Date`: `<N>d` is N days before `now`, otherwise an ISO date; anything else throws `--since takes <N>d or a date`.
- `Runtime.stats(o: { since?: string; list?: boolean })` reads `ledger.runs()` and `ledger.read({ run_id })` events, with `since` defaulting to `28d`. The CLI command `stats [--since 28d|<date>] [--list] [--json]`: human output is the counts, the clean rate as a percentage with `above` or `below the SPEC's 50% line`, the assisted totals, the `--list` lines (`<run_id>  <class>  <reasons joined by ", ">`), then the footer.

### Task 2: Eval building blocks (oracle, metrics, results, compare)

**Files:**
- Create: `packages/cli/src/eval/oracle.ts`, `packages/cli/src/eval/metrics.ts`, `packages/cli/src/eval/results.ts`
- Test: `packages/cli/test/eval-oracle.test.ts`, `packages/cli/test/eval-metrics.test.ts`, `packages/cli/test/eval-results.test.ts`

**Interfaces:**
- `oracle.ts`: `checkOracle(o: { oracle: Oracle; taskDir: string; workspace: Workspace; checkoutOf: (repo: string) => string; base: Record<string, string>; sandboxOf: (hostDir: string) => Promise<Sandbox>; timeoutMs: number }): Promise<{ solved: boolean; failures: string[] }>` where `checkoutOf(repo)` is a directory with the repo checked out at the run's result, and `base[repo]` the pinned sha. Order: first `must_not_touch` (for each entry, `git -C <checkout> diff --name-only <base>..HEAD`, repo-relative names turned project-relative with the project's `path`, each matched with `globsOverlap` against the entry's `paths`; a match fails with `must_not_touch <project>: <file>`), then copy each hidden test from `resolve(taskDir, from)` to `<checkout>/<project path>/<to>` (creating directories), then each `must_pass` runs `sandboxOf(<checkout>/<project path>)` `.exec(run, { timeoutMs })` and a non-zero code (or `timedOut`) fails with `must_pass <project>: <run> exited <code>` (or `timed out`); the sandbox is disposed after each. `solved` is `failures.length === 0`.
- `metrics.ts`: `type RunMetrics = { first_pass_valid: boolean | null; units: number; attempts: number; attempts_per_unit: number; escalations: number; stalls: number; scope_violations: number; tokens: number; wall_ms: number }` and `extractMetrics(ledger: Ledger, runId: string, wallMs: number): RunMetrics`: `first_pass_valid` is whether the first `plan.answer` event's `data.outcome` is `valid` (null when none); `units` and `attempts` from `ledger.units(runId)` and `ledger.attempts(runId)`; `attempts_per_unit = units ? attempts / units : 0`; `escalations` and `stalls` count `unit.escalated` and `unit.stalled` events of the run; `scope_violations` counts `gate.result` events with `data.gate === "diff_scope"` and `data.verdict === "fail"`; `tokens` sums `input + output` over the attempts rows (missing counted 0).
- `results.ts`:
  - `type EvalStatus = "solved" | "unsolved" | "escalated" | "missed_escalation" | "false_escalation" | "error"`; `type EvalRunResult = { schema: 1; task: string; run: number; label: string; status: EvalStatus; solved: boolean; failures: string[]; error?: string; metrics?: RunMetrics }` (solved is true for `solved` and `escalated` only).
  - `writeResult(out: string, r: EvalRunResult): string` writes `<out>/<label>/<task>/run-<run>.json` and returns the path; `resultExists(out, label, task, run): boolean`; `readResults(out: string, label: string): EvalRunResult[]` (all `run-*.json` under the label, sorted by task then run; an empty array when the label is missing).
  - `summarize(results: EvalRunResult[]): Summary` where `Summary = { label: string; runs: number; errors: number; overall: Agg; tasks: Record<string, Agg> }` and `Agg = { n: number; solved_rate: number | null; first_pass_valid_rate: number | null; false_escalation_rate: number | null; honest_escalation_rate: number | null; solved_spread: number; metrics: Record<"attempts_per_unit" | "escalations" | "stalls" | "scope_violations" | "tokens" | "wall_ms", { mean: number; min: number; max: number }> }`. `error` runs are excluded from every rate and counted in `errors`. `solved_rate` is solved over non-error runs; `first_pass_valid_rate` is over runs with a non-null `first_pass_valid`; `false_escalation_rate` is `false_escalation` over runs of tasks with an oracle (those not `escalated` or `missed_escalation`); `honest_escalation_rate` is `escalated` over `escalated + missed_escalation`; `null` when a denominator is 0. `solved_spread` is, for the overall Agg only, the max minus min of the solved rate computed per run index across tasks (0 with a single run index); per-task Aggs use 0. `metrics` mean, min and max are over runs that have metrics.
  - `compareLabels(a: Summary, b: Summary): Comparison` with `Comparison = { a: string; b: string; rows: { metric: string; a: number | null; b: number | null; delta: number | null; spread_a: number }[]; per_task: { task: string; solved_a: number | null; solved_b: number | null }[]; regressed: boolean }`; `regressed` is true when `b.overall.solved_rate` is below `a.overall.solved_rate - a.overall.solved_spread` or `b.overall.first_pass_valid_rate` is below `a.overall.first_pass_valid_rate - 0`... (use a spread of 0 for validity, so any drop regresses); rows cover the rates and each `metrics` mean; and `renderComparison(c: Comparison): string` prints one line per row (`<metric>  <a>  <b>  <delta>  (spread <n>)`) and per-task solved rates, ending `REGRESSED` or `no regression`.

- [ ] **Step 1: Write failing tests.** Oracle (temp git repos built with `git init`, commits and a scripted `Sandbox` whose `exec` returns a configured code per command): a passing run is solved; a `must_pass` exiting 2 gives `must_pass server: go test ./... exited 2`; a changed forbidden path gives `must_not_touch server: persistence/db.go` and a hidden test file added by the oracle does not itself trigger a violation (it is copied after the diff); a `timedOut` result fails with `timed out`; hidden tests land at `<project path>/<to>`; project paths other than `.` are applied. Metrics (a ledger seeded like the dashboard tests): first-pass validity true/false/null, attempts per unit, escalations, stalls, scope violations, tokens, an empty run gives zeros. Results: write/exists/read round trip; `summarize` over four runs of two tasks gives the right rates, excludes errors and counts them, computes `false_escalation_rate`, `honest_escalation_rate` and `solved_spread` (two run indices with different overall rates), per-task and overall means with min and max; `compareLabels` rows and deltas, `regressed` true when the solved rate falls by more than the spread, false within it, true for any first-pass validity drop; `renderComparison` text includes the verdict line and the per-task rates.
